# Сравнение алгоритмов поиска

## Протокол

Все алгоритмы индексируют один англоязычный корпус. Разметка определяет релевантность по идентификаторам документов отдельно для каждого запроса. Набор dev используется для выбора настроек. Набор test используется для итогового сравнения после фиксации настроек.

- Precision@10 равна числу релевантных документов среди первых десяти результатов, делённому на 10. Пропущенные позиции считаются нерелевантными.
- Recall@10 равна числу релевантных документов среди первых десяти результатов, делённому на общее число размеченных релевантных документов.
- MRR усредняет обратный ранг первого релевантного результата по всем запросам. При отсутствии релевантного результата вклад равен нулю.
- Среднее время запроса относится к выдаче первых десяти документов из заранее построенного индекса. Вычисление эмбеддинга запроса входит в измерение для семантического поиска.
- В финальном протоколе пиковый RSS читает отдельный процесс измерения из поля `VmHWM` в `/proc/self/status` после построения индекса, прогрева и замера top-10. Он включает интерпретатор, загруженные данные и библиотеки, индекс и модель. Оценка качества выполняется после фиксации RSS.

Метрики качества усредняются по запросам с одинаковым весом. Задержка усредняется по 20 проходам после одного прохода прогрева. Библиотеки численных вычислений ограничены одним потоком в бенчмарке. История измерений хранится в `BENCHMARKS.csv`. Поле `rss_source` различает методы замера памяти. Итерации 1–3 использовали `ru_maxrss`. Reviewer установил, что на Linux этот счётчик может учитывать пик памяти процесса до `exec`. В итерации 4 сетку и контрольный прогон повторили с `VmHWM`.

## Алгоритмы

- **TF-IDF** использует исходную частоту терма, сглаженный IDF и косинусное сходство. Разреженный индекс хранит взвешенные вхождения термов.
- **BM25** вводит насыщение частоты и поправку на длину документа. Вариант проекта использует положительный IDF Lucene и учитывает повтор терма в запросе. Вклад каждого терма предвычисляется при индексации.
- **MiniLM** кодирует заголовок с текстом и запрос в 384-мерные векторы. Он работает в ONNX Runtime на CPU, усредняет скрытые состояния по маске, нормирует их и выполняет точный поиск по косинусу. Документы обрабатываются в фиксированном порядке батчами по восемь, запросы по одному.
- **Гибрид** складывает `w / (c + rank_BM25)` и `(1 - w) / (c + rank_MiniLM)`. Ранги начинаются с единицы. При отсутствии документа в компонентной выдаче её вклад равен нулю. Все методы разрешают равенство оценок по ID документа.

## Наборы запросов

| Набор | Прямые | Перефразированные | С близкими отвлекающими документами | Максимальная средняя Precision@10 |
| --- | ---: | ---: | ---: | ---: |
| dev | 4 | 3 | 3 | 0,24 |
| test | 6 | 6 | 8 | 0,14 |

В dev на запрос приходится два или три релевантных документа, в test один или два. Это ограничивает достижимую Precision@10 и требует сравнивать методы внутри одного набора.

## Настройка на dev

На первой итерации TF-IDF получил Precision@10 0,2000, Recall@10 0,8167 и MRR 0,8333 на десяти запросах dev.

BM25 при `k1=0.6`, `b=0.75` сравнялся с TF-IDF на dev по всем метрикам качества. BM25 с `k1=1.2` дал MRR 0,8250. Выбор `k1=0.6` объясняется одним запросом, в котором первый релевантный документ поднялся с четвёртой на третью позицию.

MiniLM нашёл на dev все 24 размеченные пары «запрос — документ», а первый релевантный документ стоял на первом месте для каждого запроса. Контрольный прогон третьей итерации дал 3,208 мс на запрос для MiniLM и около 0,025 мс для лексических методов.

В гибриде три из восьми конфигураций также дали Precision@10 0,24, Recall@10 1,00 и MRR 1,00. Среди них выбраны вес BM25 0,25 и константа RRF 10 по заранее заданному правилу. Конфигурации и код закреплены коммитом `631c728` перед итоговым прогоном.

## Результаты на test

Один итоговый прогон на 20 запросах. Окружение Codex Cloud, Debian 13, Linux 6.18.57, AMD EPYC 9V74 с тремя доступными vCPU и AVX2. Python 3.12.14, NumPy 2.3.5, ONNX Runtime 1.32.0, Tokenizers 0.23.3.

| Метод | Precision@10 | Recall@10 | MRR | Среднее время, мс | Пиковый RSS, МиБ |
| --- | ---: | ---: | ---: | ---: | ---: |
| TF-IDF | 0,11 | 0,825 | 0,7114 | 0,032 | 16,60 |
| BM25 | 0,12 | 0,875 | 0,7528 | 0,029 | 16,60 |
| MiniLM | 0,14 | 1,000 | 0,9250 | 4,045 | 128,62 |
| BM25 + MiniLM | 0,14 | 1,000 | 0,9250 | 4,722 | 129,01 |

MiniLM и гибрид вернули в top-10 все 28 размеченных пар «запрос — документ». Их MRR совпал. Среднее время гибрида было на 16,7% выше, поэтому на этом наборе MiniLM даёт то же измеренное качество с меньшей задержкой.

BM25 улучшил все три метрики качества относительно TF-IDF. Пиковый RSS обоих лексических методов составил 16,60 МиБ. Небольшая разница их задержек относится к этому прогону. MiniLM повысил Recall@10 относительно BM25 на 12,5 процентного пункта и использовал 128,62 МиБ пикового RSS.

Результаты относятся к небольшому англоязычному лабораторному корпусу. Задержка измерена для уже построенного индекса, а разовый вызов CLI также строит индекс. Семантический метод усекал вход до 256 токенов и сравнивал запрос со всеми векторами, поэтому результаты по качеству и скорости зависят от длины и размера корпуса.
