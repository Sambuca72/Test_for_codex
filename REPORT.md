# Сравнение алгоритмов поиска

## Протокол

Все алгоритмы индексируют один англоязычный корпус. Разметка определяет релевантность по идентификаторам документов отдельно для каждого запроса. Набор dev используется для выбора настроек. Набор test используется для итогового сравнения после фиксации настроек.

- Precision@10 равна числу релевантных документов среди первых десяти результатов, делённому на 10. Пропущенные позиции считаются нерелевантными.
- Recall@10 равна числу релевантных документов среди первых десяти результатов, делённому на общее число размеченных релевантных документов.
- MRR усредняет обратный ранг первого релевантного результата по всем запросам. При отсутствии релевантного результата вклад равен нулю.
- Среднее время запроса относится к выдаче первых десяти документов из заранее построенного индекса. Вычисление эмбеддинга запроса входит в измерение для семантического поиска.
- Пиковый RSS измеряется в отдельном процессе Linux через `ru_maxrss` после построения индекса, прогрева и замера top-10. Он включает интерпретатор, загруженные данные и библиотеки, индекс и модель. Оценка качества выполняется после фиксации RSS.

Метрики качества усредняются по запросам с одинаковым весом. Задержка усредняется по 20 проходам после одного прохода прогрева. Библиотеки численных вычислений ограничены одним потоком в бенчмарке. История измерений хранится в `BENCHMARKS.csv`.

## Наборы запросов

| Набор | Прямые | Перефразированные | С близкими отвлекающими документами | Максимальная средняя Precision@10 |
| --- | ---: | ---: | ---: | ---: |
| dev | 4 | 3 | 3 | 0,24 |
| test | 6 | 6 | 8 | 0,14 |

В dev на запрос приходится два или три релевантных документа, в test один или два. Это ограничивает достижимую Precision@10 и требует сравнивать методы внутри одного набора.

## Результаты

На первой итерации TF-IDF получил Precision@10 0,2000, Recall@10 0,8167 и MRR 0,8333 на десяти запросах dev. Итоговая выборка test сохранена для финального прогона.

BM25 при `k1=0.6`, `b=0.75` сравнялся с TF-IDF на dev по всем метрикам качества. BM25 с `k1=1.2` дало MRR 0,8250. Выбор `k1=0.6` объясняется одним запросом, в котором первый релевантный документ поднялся с четвёртой на третью позицию.

MiniLM нашёл на dev все 24 размеченные пары «запрос — документ», а первый релевантный документ стоял на первом месте для каждого запроса. Контрольный прогон дал 3,208 мс на запрос и пиковый RSS 128,13 МиБ. Лексические методы в том же прогоне занимали около 0,025 мс и 14 МиБ.
