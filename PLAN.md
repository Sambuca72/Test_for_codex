# План эксперимента

| Итерация | Реализация | Проверка |
| --- | --- | --- |
| 1 ✓ | Воспроизводимый корпус, разметка dev/test, TF-IDF и CLI | Независимые тесты и контрольный замер на dev |
| 2 → | BM25 | Сравнение с TF-IDF и выбор параметров по dev |
| 3 | Компактная открытая модель эмбеддингов на CPU | Проверка работы модели, замер на тех же dev-запросах |
| 4 | Гибридное ранжирование | Выбор параметров по dev, фиксация конфигураций, сравнение на test и аудит |

Корпус один для всех алгоритмов. Итоговую выборку test открываем для сравнительных замеров после фиксации всех настроек. Тесты целостности могут читать оба набора.

Developer владеет кодом и корпусом. Researcher проверяет источники и передаёт рекомендации Developer. Reviewer владеет независимыми тестами и кодом бенчмарка. Оркестратор сохраняет контрольные точки и отчёты. В каждый момент работают не более двух субагентов.
